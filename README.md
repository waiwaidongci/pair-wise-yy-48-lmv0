# 消防报警系统联动逻辑配置与调试审阅平台

面向消防工程师、调试人员和审阅人的联动逻辑工作台，支持设备台账、因果矩阵、互锁/延时/优先级配置、矩阵校验、依赖图、版本差异、联调清单、签字锁定，以及**夜班现场批次交接**。

## 技术栈

Vue 3 + Vuetify + Pinia + Vue Router + Apollo Client + GraphQL + Vite + TypeScript

## 本地运行

```bash
npm install
npm run dev
```

访问 `http://localhost:62048`。

## 测试

```bash
npm test          # 交接内核 65 项断言 + 浏览器互斥锁并发测试
```

- `src/sync/core.ts`：纯 TS 交接内核，不依赖 Vue/DOM，可在 Node 直接验证。
- `scripts/run-selftest.mjs`：经 esbuild 转译后运行 `src/sync/selftest.ts`。

## 核心工作流

- 按楼层分区维护探测器、模块和消防设备，建立触发到动作的因果矩阵。
- 配置延时、互锁、优先级和抑制条件，并批量启停或修改矩阵规则。
- 自动发现遗漏、重复、自相矛盾、悬空引用和跨区冲突，在依赖图中定位问题。
- 比较专业提交版本并部分接受变更，完成联调清单后签字锁定交付包。

## 现场批次交接（断网—恢复）

夜班调试员断网改条件、恢复后不能把已签字基线或另一窗口的新修改盖掉，因此所有改动走批次协议：

1. **顺序记录 + 打开版本**：每个窗口开批时记下基线版本（如 R8），改动按连续序号（#1、#2…）写入本机批次（`sessionStorage`，窗口间互不覆盖），每条还记录落笔时的实体版本号。
2. **恢复先看基线**：重新连接先拉取当前版本：
   - 基线**没有前进**：整批一次 CAS 快进推进（`fast-forward`）。
   - 基线**已经前进**：按设备、规则**逐条重放**，条目间逐次比对实体版本。
3. **双方都改过 → 留待确认**：同一条目两边都动过则标记冲突，双方版本并列展示，绝不自动覆盖；确认后可「保留本机版」（按当前版本登记新序号续推）或「采用当前版」（丢弃本机条目）。
4. **签字内容不可覆盖**：服务器已签字时整批阻断（批次原样保留）；本机签字工作区只读；签字/解锁动作本身也是批次条目，推进后才生效。
5. **同时提交只准一份**：跨窗口自旋锁 + 服务器推进占用（claim）保证同一时刻只有一个批次推进；落败方**保留原批次**，可查看当前版本和获胜对象，再以当前版本重放（同改条目同样转留验）。
6. **中断续传**：重放中途中断时已落库条目立即固化进一个新版本，占用保留；续传从最后完整序号之后继续，已完成条目不重复。
7. **派生状态联动失效**：设备、规则或签字状态变化（本机或对侧）时，依赖图、矩阵校验、审阅状态和校验和一起失效并自动重算。
8. **旧草稿补版本**：缺少打开版本的旧草稿（`fire-linkage-draft-v1`）首次打开时补登首版 R8，差异按序号转出后照常开批。

服务端基线存于 `localStorage`（跨标签页共享），可用浏览器开两个标签页，配合「现场批次交接」页右侧的演练台（断网、对侧推进、对侧签字、中断）演示完整流程。
